# ─────────────────────────────────────────────────────────────────────────────
# Container dependency set for the IRIS backend (Linux / python:3.13-slim).
#
# WHY THIS FILE EXISTS instead of using requirements.txt directly:
#
#   1. requirements.txt lines 2-161 are an unpinned `pip list`-style dump (name
#      only, no versions), then lines 162-180 re-declare ~12 of the same packages
#      WITH constraints. fastapi, pydantic, redis, httpx, tenacity, orjson,
#      python-dotenv, sqlalchemy and uvicorn each appear twice. An unpinned build
#      is not reproducible: the image you test is not the image you ship.
#
#   2. It requires `python-magic-bin`, which publishes Windows/macOS wheels ONLY.
#      `pip install` fails outright on Linux. Nothing in the codebase imports
#      `magic` — upload sniffing uses `filetype` (pure Python), so the dependency
#      is dropped rather than swapped for python-magic + the libmagic1 apt package.
#
#   3. It pulls torch, transformers, sentence-transformers, scikit-learn, scipy and
#      pyiceberg — together several GB of wheels. An AST scan of all 39 root .py
#      files finds ZERO imports of any of them. Dropped.
#
#   4. It lists `pip`, `setuptools` and `uv` (the dev environment's own tooling)
#      and `colorama` (a Windows terminal shim). None belong in a server image.
#
# HOW THIS LIST WAS DERIVED: every top-level import across the 39 root .py files
# was resolved to its installed distribution via importlib.metadata, then pinned
# to the exact version running in project_venv — so the container matches the
# environment the code was actually verified against. Runtime-only packages that
# no module imports directly are listed separately at the bottom.
#
# REGENERATE after adding a dependency; do not hand-edit versions.
# ─────────────────────────────────────────────────────────────────────────────
